# CONDYN / SYNTX — CANONICAL ARCHITECTURAL INVARIANTS v1.0

This document defines the **8 Canonical Architectural Invariants** of the CONDYN / SYNTX Decision Infrastructure.
These invariants represent immutable laws of the platform. Any code change, refactoring, or feature addition that violates any of these invariants is **UNACCEPTABLE** and will fail the `Decision Integrity Suite` (`test/career-decision-integrity.test.ts`).

---

## Invariant 1 — Everything is evidence until it becomes a decision
Every decision, matching score, recommendation, or ranking produced by the system must be explainable back to verifiable evidence.
No entity or recommendation may exist without grounding in one or more evidence items.

```text
Source ──► Evidence ──► Capability ──► Requirement ──► Job / Decision
```

---

## Invariant 2 — Nothing becomes knowledge until it has survived validation
Raw model inference outputs or unparsed inputs are never treated as canonical knowledge.
Every extraction must pass runtime Zod validation (`VerifiedCareerAnalysis`) and schema verification before entering the graph.

---

## Invariant 3 — The UI never traverses the graph (Dumb Consumer UI)
User interface components (`SIL v3.0`, `Planetarium`, `DecisionGraphInspector`) are strictly **Dumb Consumers**.
The UI never performs graph traversals, path finding, or confidence math. It receives `DirectedEvidenceGraph`, `GraphFocus`, or `CurrentGraphState` from `lib/career/evidence` and `lib/career/confidence` and renders them declaratively.

---

## Invariant 4 — Evidence Graph is the single source of truth
All downstream calculations (job mappings, organisation rankings, proof chains, and HUD visualisations) consume the `DirectedEvidenceGraph`.
No duplicated graph logic or parallel state structures are permitted.

---

## Invariant 5 — All recommendations must be explainable back to evidence
Every recommendation generated by `lib/career/recommendations` or `lib/career/matching` must maintain an explainable trace:
`Recommendation -> Requirement -> Capability -> Evidence -> Source`.
Orphaned recommendations without a trace are invalid.
Furthermore, **explainability never exceeds fit**: An explanation score (`explainabilityScore`) cannot exceed the underlying evidence-grounded fit score (`fitScore`).

---

## Invariant 6 — Simulation never mutates the base graph
What-If Simulations (`simulateEvidenceImpact` in `lib/career/confidence/graph-state.ts`) operate strictly as pure, side-effect-free calculations over deep-cloned graph structures.
Executing a simulation must leave the base graph byte-identical.

---

## Invariant 7 — Confidence propagation is strictly deterministic
Given identical input sources, evidence scores, and source weights, the Confidence Propagation Engine (`propagateGraphConfidence` in `lib/career/confidence/propagation.ts`) must produce identical propagated confidence values every time. No randomness or unseeded stochastic drift is allowed.

---

## Invariant 8 — All scores originate from the graph
Job match scores, capability fulfillment percentages, and organisation rankings must originate directly from the `DirectedEvidenceGraph` and its propagated confidence layer.
Manual overrides or arbitrary score injections outside graph physics are strictly prohibited.
