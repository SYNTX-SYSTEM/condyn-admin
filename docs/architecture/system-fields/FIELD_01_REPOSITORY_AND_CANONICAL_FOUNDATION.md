# Field 01 — Repository and Canonical Foundation

## Status

Planned. This is the prerequisite semantic field for Fields 02 and 03.

## Semantic objective

Reconcile the mixed local worktree into one classified canonical execution
foundation: precise contracts and fixtures, immutable persistence registration,
production initialization, exact reread, and type/build/regression closure.

## Current executable state

The repository contains preserved T47/T48/T49 feedback-context work, canonical
relation contracts and PostgreSQL adapters, `lib/career/repositories/postgres.ts`,
`lib/career/db/client.ts`, and production SIL schema/read code. It also contains
untracked decision-authority and execution authority/context overlays, broad
TypeScript failures, stale immutable-fixture assumptions, and host-gated
PostgreSQL/runtime execution. The overlay is not disposable: classify each
component as canonical continuation, compatibility layer, superseded local
experiment, test infrastructure, or semantic conflict before modifying it.

## Ingress and authority

Ingress is existing canonical source, preserved WIP, tests, schemas, startup
composition, and sealed predecessor contracts. Authority is deterministic
repair of already-sealed relations only. This field must not hide WIP from
TypeScript, weaken strictness, manufacture currentness, or reinterpret the
Decision/Execution chain for a green build.

## Scope and egress

Scope includes runtime refinement, fixtures, Decision Authority, Execution
Authority, Execution Context, T5–T11 reconciliation, production Postgres
registration, FK order, schema alignment, bootstrap, exact reread, immutable
conflict/idempotency, typecheck, build, and broad regression classification.
Egress is a coherent canonical classification with no unexplained locally owned
type/build/test defect. Remaining blockers must be explicitly host, provider,
legacy quarantine, semantic authority, product decision, or overlay
reconciliation boundaries.

## Internal work units

1. Reconstruct and classify the overlay plus all compiler/test root clusters.
2. Close canonical contract/fixture and persistence/startup defects through
   exact reread and restart proof.
3. Run repository-wide type/build/regression gates and classify residuals.

## Persistence and replay scope

Use existing immutable repository contracts only. For each registered artifact,
prove insert, exact reread, same-ID/same-payload idempotency, divergent
same-ID conflict, FK ordering, and restart behavior where a replay mode exists.
Do not invent replay modes or treat a durable row as authority.

## Recursive regression graph

contract → constructor → admission/application → repository/schema → startup
composition → exact reread/replay → direct consumer → integration → typecheck
→ production build → broad regression.

## Completion and stop conditions

Complete only when the stated egress holds. Stop a branch at unavailable host
capability, external provider trust, human/product authority, or an unresolved
overlay semantic conflict. Document the boundary; preserve WIP; do not repair
around it.

## Report contract

Report overlay classification, root defects, changed files, RED/GREEN evidence,
persistence/startup proof, all gate results, remaining boundaries, and the
Field 02/03 readiness decision.
