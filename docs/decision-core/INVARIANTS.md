# Decision Core invariants

This table records enforcement present through Phase 5C4. Phase 5C2 records semantic evaluator proposals, Phase 5C3A records explicit structural comparison targets, Phase 5C3B records explicit structural relation proposals, Phase 5C3C derives basis-relative structural gaps, Phase 5C3D derives explicit-path basis-relative `StructuralConsequence` artifacts from validated item-anchored gaps and explicit ordered dependency paths, and Phase 5C4 assembles revalidated derivational coherence. None establishes verified semantic truth, global completeness, current authority, decision readiness, decision need, recommendation, or human decision.

| Rule | Why | Enforcement location | Failure mode / contract |
| --- | --- | --- | --- |
| Authority dependencies are bound at construction. | Callers must not redirect an existing reader or validator with a replacement resolver method. | `authority/reader.ts`; `validation/authority.ts`. | Reader/validator capture and bind `resolve` once, preserving `this`. Contract tests mutate methods after construction. |
| `AuthoritativeStateReference` carries no payload or resolver. | State content and authority dependency must remain separate from caller input. | `authority/types.ts`; strict reader reference capture. | Type-level/runtime contract tests; malformed runtime references fail `ERR_DECISION_AUTHORITY_REFERENCE_INVALID`. |
| A successful resolution does not confer portable authority. | A returned object must not certify future authority. | `AuthoritativeStateResolution` documentation and reader/validator APIs. | Reader returns a descriptive resolution; 5C1 returns `Promise<void>`. No API accepts a prior resolution as authority. |
| Resolver identity is `producerId + authorityContractId`. | A producer contract, not caller payload shape, selects a resolver. | `resolverBindingKey`; bound-reader map. | Unknown binding: `ERR_DECISION_AUTHORITY_RESOLVER_NOT_FOUND`; duplicate/invalid registration: `ERR_DECISION_AUTHORITY_RESOLVER_CONFLICT`. |
| The Capability adapter validates a persisted Phase-4 snapshot before returning state. | A SNAP-like shape or prefix is not sufficient producer authority. | `decision-adapters/capability-core.ts`. | Missing state: `ERR_DECISION_AUTHORITY_STATE_NOT_FOUND`; invalid snapshot: `ERR_DECISION_AUTHORITY_STATE_INVALID`; locator/artifact mismatch: `ERR_DECISION_AUTHORITY_ARTIFACT_REFERENCE_MISMATCH`. |
| A context has exactly one `DECISION_QUESTION`. | `decisionQuestionId` is derived from one canonical question item. | `context/contract.ts`. | `ERR_DECISION_CONTEXT_DECISION_QUESTION_COUNT`. |
| Zero options, objectives, and constraints are valid. | Phase 5B represents structural drafts before completeness/gap analysis. | Context constructor/assertion contract. | No error solely for their absence. |
| Role and provenance are independent axes. | An objective/observation/constraint does not establish who supplied it or its epistemic status. | `DecisionContextItem` plus discriminated provenance union. | Identity includes both role and canonical provenance; no origin conversion occurs. |
| Provenance origins are closed in Phase 5B. | The draft records source category without collapsing categories. | `DecisionContextItemProvenance`. | Exactly `AUTHORITATIVE_STATE`, `HUMAN_INPUT`, `MODEL_PROPOSAL`, `DETERMINISTIC_DERIVATION`; invalid fields/origins fail `ERR_DECISION_CONTEXT_ITEM_INVALID`. |
| Draft validation status is always `NOT_RUN`. | Structural construction does not resolve or semantically validate authority. | `DecisionContextDraft`; constructor/assertion. | Any other status fails `ERR_DECISION_CONTEXT_INVALID`. |
| `DCI_` identity is deterministic. | Same canonical item content must have one item identity independent of input position. | `context/identity.ts`. | Item IDs are recomputed during assertion; mismatch fails `ERR_DECISION_CONTEXT_ITEM_ID_MISMATCH`. |
| `DCTX_` identity is deterministic. | Canonical reference/item sets must produce one canonical context artifact. | `context/identity.ts`; constructor/assertion. | Context mismatch: `ERR_DECISION_CONTEXT_ID_MISMATCH`. |
| Source references are canonical and unique. | A source inventory must not silently duplicate or reorder identity-bearing references. | Context constructor/assertion. | Duplicate: `ERR_DECISION_CONTEXT_DUPLICATE_SOURCE_STATE_REFERENCE`; noncanonical order: `ERR_DECISION_CONTEXT_SOURCE_STATE_REFERENCES_NOT_CANONICAL`. |
| Context items are canonical and identity-checked. | Stored item content cannot diverge from its ID or order. | Context constructor/assertion. | Duplicate: `ERR_DECISION_CONTEXT_DUPLICATE_ITEM`; noncanonical order: `ERR_DECISION_CONTEXT_ITEMS_NOT_CANONICAL`; invalid item: `ERR_DECISION_CONTEXT_ITEM_INVALID`. |
| `AUTHORITATIVE_STATE` provenance must refer to a listed source reference. | The draft may reference authority only through its declared source inventory. | `assertQuestionAndAuthoritativeReferences`. | `ERR_DECISION_CONTEXT_AUTHORITATIVE_REFERENCE_MISSING`. This is structural presence, not current resolvability. |
| Context carries no later-phase recommendation/decision semantics. | A draft is not assessment, recommendation, decision, action, outcome, or feedback state. | `DecisionContextDraft`/`DecisionContextItem` type contracts and public-export gates. | No such fields/types are exported by the Phase-5B context surface. |
| 5C1 validates the complete context before resolution. | A malformed context must not trigger any reader call. | `captureContextReferences` then `assertDecisionContextDraft`. | `ERR_DECISION_CONTEXT_AUTHORITY_CONTEXT_INVALID`; contract test proves zero reader calls. |
| 5C1 resolves detached captured references. | Caller mutation after validation begins must not change later resolver inputs. | `validation/authority.ts`. | Detached capture before awaits; tests cover asynchronous caller mutation. |
| Reader mutation cannot redirect an existing validator. | The reader is a construction-time authority dependency. | `bindResolve`. | Invalid reader: `ERR_DECISION_CONTEXT_AUTHORITY_READER_INVALID`; replacement method is not invoked. |
| Returned resolution reference must equal the requested reference exactly. | A resolver result for another artifact cannot satisfy the request. | `captureResolutionReference`; `sameReference`. | `ERR_DECISION_CONTEXT_AUTHORITY_REFERENCE_MISMATCH`. |
| 5C1 ignores resolution payload semantics. | Authority reachability is not semantic evidence binding. | Validator loop reads only `resolution.reference`. | Payload is neither returned nor inspected, hashed, persisted, or interpreted. |
| Empty authority inventory is valid. | A context may legitimately have no source references before later completeness analysis. | Validator loop. | Zero bound-reader calls; successful `Promise<void>`. |
| Successful 5C1 validation returns `Promise<void>`. | It must not create a reusable authority bundle, certificate, or validated context artifact. | `BoundDecisionContextAuthorityValidator`. | Success has no value; later operations must resolve again. |
| Validation production remains generic. | Generic Decision Core must not take on producer/domain ontology. | `test/decision-core/validation/authority.test.ts` AST import gate. | Validation sources may not import Career, Capability Core, matching, recommendation, or legacy decision-looper paths. |
| Validation public surface excludes Phase-5C2+ concepts. | Later semantic-analysis/decision artifacts must not appear early as public types or values. | Compiler-resolved validation export gate. | No public `EvidenceBinding`, support states, gaps, contradictions, dependencies, consequences, recommendations, scores, rankings, human decisions, actions, outcomes, or feedback. |
| Phase-5C2 evaluator and reader dependencies are bound at construction. | A caller must not redirect an existing semantic binder by replacing methods after composition. | `evidence-binding/binder.ts`. | `bindResolve` and `bindEvaluate` capture methods with receivers; contract tests prove replacement resistance and `this` preservation. |
| A binding is exactly one item × one listed state reference. | Semantic support is an explicit relation, not inferred from context role or provenance. | `SemanticEvidenceBindingProposal`; evaluator-output capture. | Unknown item: `ERR_DECISION_EVIDENCE_BINDING_ITEM_NOT_FOUND`; foreign/mismatched reference: `ERR_DECISION_EVIDENCE_BINDING_STATE_REFERENCE_INVALID`. |
| Binding dispositions are closed. | Phase 5C2 must not encode uncertainty, confidence, score, or ranking. | `EVIDENCE_BINDING_DISPOSITIONS`. | Only `SUPPORTED`, `PARTIALLY_SUPPORTED`, `NOT_SUPPORTED`, `CONTRADICTED`; malformed output fails `ERR_DECISION_EVIDENCE_BINDING_EVALUATION_INVALID`. |
| Provenance does not imply semantic support. | Origin and item/state semantic relationship are independent axes. | Binder accepts evaluator proposals for any provenance. | Tests show `HUMAN_INPUT` may be `SUPPORTED`, `MODEL_PROPOSAL` may be `CONTRADICTED`, and `AUTHORITATIVE_STATE` has no automatic support. |
| Complete operation-time authority preparation precedes semantic evaluation. | No evaluator may inspect one state while another context source remains unresolved or unsafe. | Stage A followed by Stage B in `evidence-binding/binder.ts`. | Any resolution, returned-reference, or payload-isolation failure invokes the evaluator zero times. |
| Semantic payload inspection cannot mutate resolver-owned producer payload. | Shared mutable producer memory is not semantic evaluator capability. | `detachSemanticPayload`; shared-memory graph inspection. | Non-cloneable or shared-memory payload: `ERR_DECISION_EVIDENCE_BINDING_PAYLOAD_NOT_DETACHABLE`; evaluator is not invoked. |
| Semantic payload isolation is Phase-5C2-specific. | Generic Phase-5A resolution returns a resolver-owned opaque payload without cloning it. | Stage-A `structuredClone` plus post-clone inspection. | Phase 5C2, not Phase 5A, establishes evaluator payload isolation. |
| `EBIND_` identity excludes rationale wording. | Free-language explanation must not alter the identity of the item/state/disposition relationship. | `evidence-binding/identity.ts`. | Exact identity tests prove rationale changes retain ID; disposition changes ID. |
| Duplicate item/reference binding targets reject and output is canonical. | The same relationship must not silently carry divergent evaluator proposals or order-dependent output. | Target-key and ID sets; deterministic binding-ID sort. | `ERR_DECISION_EVIDENCE_BINDING_DUPLICATE`; canonical `SemanticEvidenceBindingProposal[]`. |
| Zero semantic proposals are valid. | Unexamined relationships are not negative support findings, and Phase 5C2 does not assess completeness. | Evaluator/binder contract. | `[]` returns without synthesizing `NOT_SUPPORTED`; no gap/completeness claim. |
| `CONTRADICTED` is not a structural contradiction finding. | A single evaluator proposal cannot establish the later cross-binding/context Phase-5C3 concept. | Phase-5C2 public contract/export gate. | No public `Contradiction`, Gap, Dependency, Consequence, Recommendation, Score, Ranking, HumanDecision, Action, Outcome, or Feedback artifact. |
| Evidence-binding production remains generic and excludes Phase-5C3+ concepts. | The generic kernel must not acquire Career/Capability semantics or future decision-analysis surface. | `test/decision-core/evidence-binding/contract.test.ts` AST import/public-export gates. | No Career, Capability Core, matching, recommendation, or legacy decision-loop import; no forbidden Phase-5C3+ public export. |
| Absence is not a Gap. | Missing items, roles, bindings, or dispositions have no defined comparison target until an explicit expectation exists. | `structural-findings/expectation.ts` exposes construction/assertion only. | Phase 5C3A derives or represents no Gap and performs no satisfaction evaluation. |
| A `StructuralExpectation` is a comparison target only. | Expected structure must remain distinct from observed structure and from a derived finding. | `StructuralExpectation` contract. | Phase 5C3A performs structural membership checks for referenced items and authoritative-state provenance references, but performs no expectation-satisfaction evaluation against current role counts, `SemanticEvidenceBindingProposal[]`, dependency findings, or other observed relation state. |
| Structural expectation kinds are closed. | Phase 5C3A must not encode findings, decision need, priority, or recommendations as expectations. | `STRUCTURAL_EXPECTATION_KINDS`. | Exactly `EVIDENCE_BINDING`, `CONTEXT_ROLE`, and `DEPENDENCY`; no fourth kind. |
| Expectation provenance is origin only. | A human, model, deterministic, or authoritative-state origin must not establish fact, requirement, truth, or satisfaction. | Reused `DecisionContextItemProvenance`; expectation identity tuple. | No origin conversion occurs; model proposal remains proposal state and human input remains distinct. |
| `AUTHORITATIVE_STATE` expectation provenance requires context membership only. | The reference must be declared by the context without treating that membership as current authority or satisfaction. | `requireContextReference`. | Missing or malformed/unlisted reference: `ERR_DECISION_STRUCTURAL_EXPECTATION_REFERENCE_INVALID`; no authority resolution occurs. |
| Phase 5C3A performs no authority resolution or semantic binding evaluation. | Structural expectation construction must not consume payloads or conflate expectation with support. | `structural-findings/expectation.ts`. | No reader, resolver, repository, evaluator, or binder dependency exists in the API. |
| Evidence-binding accepted dispositions are explicit and canonical. | An expectation criterion must be deterministic without asserting that any binding exists. | `canonicalizeDispositions`. | Only sealed Phase-5C2 dispositions; stored order follows `SUPPORTED`, `PARTIALLY_SUPPORTED`, `NOT_SUPPORTED`, `CONTRADICTED`. |
| Duplicate accepted dispositions reject rather than deduplicate. | Caller ambiguity must not be silently repaired. | `canonicalizeDispositions`. | `ERR_DECISION_STRUCTURAL_EXPECTATION_DUPLICATE_DISPOSITION`. |
| `CONTEXT_ROLE.minimumCount` is a positive safe integer. | A structural threshold must be finite and meaningful without evaluating it. | `captureInput`. | Invalid role/count: `ERR_DECISION_STRUCTURAL_EXPECTATION_INPUT_INVALID`. |
| Dependency expectation direction is identity-bearing and self-dependency rejects. | A depends on B differs from B depends on A; an item cannot be its own prerequisite in this contract. | Dependency canonical body; `captureInput`. | Direction changes `DEXP_`; self-dependency: `ERR_DECISION_STRUCTURAL_EXPECTATION_INPUT_INVALID`. |
| `DEXP_` identity is deterministic. | One canonical context/kind/body/provenance tuple must produce one explicit expectation identity. | `structural-findings/identity.ts`. | Recomputed during assertion; mismatched valid stored ID: `ERR_DECISION_STRUCTURAL_EXPECTATION_ID_MISMATCH`. |
| Constructor canonicalization differs from stored-artifact assertion. | Canonical equivalence must not permit a mutable stored representation to be silently repaired. | `createStructuralExpectation`; `assertStoredDispositionsCanonical`. | Constructor orders valid input; a reordered stored `acceptedDispositions` representation fails `ERR_DECISION_STRUCTURAL_EXPECTATION_INVALID`. |
| Returned expectation artifacts detach from caller input. | Later mutation of nested caller-owned arrays or provenance objects must not alter the constructed artifact. | Recursive descriptor capture plus `structuredClone` return. | Contract test mutates caller-owned input after construction; artifact remains unchanged. |
| Structural-findings public surface excludes findings and decision concepts. | Explicit expectations must not accidentally expose Gap, Dependency finding, or decision-intelligence artifacts. | Compiler-resolved export gate in `expectation.test.ts`. | No public Gap, Contradiction, Dependency finding, Consequence, DecisionNeed, Recommendation, Score, Confidence, HumanDecision, Action, Outcome, or Feedback. |
| Structural-findings production remains generic. | The generic kernel must not acquire Career, Capability Core, matching, recommendation, or legacy decision-loop coupling. | AST module-specifier gate in `expectation.test.ts`. | No forbidden production import. |
| Structural relation proposals are proposals only. | Caller-supplied relation content must remain distinct from relation truth and findings. | `StructuralRelationProposal` contract. | No relation validation, finding, Gap, Consequence, Decision Need, or recommendation artifact is constructed. |
| Relation ontology does not perform relation discovery. | Item roles, text, provenance, semantic bindings, expectations, authority state, similarity, and absence are not relation detectors. | `structural-findings/relation.ts` accepts only context plus explicit relation input. | No detector, evaluator, analyzer, inference engine, or graph traversal API exists. |
| CONTRADICTION is symmetric but stored canonicality is strict. | Equivalent constructor endpoint order must not create alternate proposals, while stored representations cannot be silently repaired. | Contradiction input capture and stored canonicality assertion. | Constructor sorts distinct endpoints deterministically; reversed stored endpoints fail `ERR_DECISION_STRUCTURAL_RELATION_INVALID`. |
| DEPENDENCY is directional and identity-bearing. | A dependent/prerequisite proposal is not interchangeable with its reverse. | Dependency relation body and DREL calculation. | Reversing otherwise valid stored endpoints with the old ID fails `ERR_DECISION_STRUCTURAL_RELATION_ID_MISMATCH`; self relation fails `ERR_DECISION_STRUCTURAL_RELATION_INPUT_INVALID`. |
| Relation endpoints require context item membership. | A proposal can only name items from its bound context. | `requireContextItem`. | Missing endpoint: `ERR_DECISION_STRUCTURAL_RELATION_ITEM_NOT_FOUND`. |
| `AUTHORITATIVE_STATE` relation provenance requires context-reference membership only. | Origin membership must not become current authority proof or relation truth. | `requireContextReference`. | Malformed or unlisted reference: `ERR_DECISION_STRUCTURAL_RELATION_REFERENCE_INVALID`; no authority resolution occurs. |
| Relation provenance is identity-bearing but not relation truth. | Human, model, deterministic, and authoritative origins must stay distinct without establishing truth. | Canonical provenance in the DREL tuple. | Changing provenance changes `DREL_`; no origin conversion or truth claim occurs. |
| `DREL_` identity is deterministic. | A canonical context/kind/body/provenance tuple must have one local proposal identity. | `structural-findings/relation-identity.ts`. | Recomputed during assertion; wrong ID on an otherwise valid canonical proposal fails `ERR_DECISION_STRUCTURAL_RELATION_ID_MISMATCH`. |
| Stored representation validation precedes variant reparsing. | Missing or extra stored top-level fields are representation failures, not constructor-input failures. | `proposalInputFromArtifact`. | Hostile/malformed stored representation, invalid header, missing/extra keys, and noncanonical contradiction order fail `ERR_DECISION_STRUCTURAL_RELATION_INVALID`; exact stored representation with invalid variant content may preserve specific errors. |
| Returned relation artifacts detach from caller input. | Mutation of caller-owned endpoint arrays or provenance objects cannot alter a constructed proposal. | Recursive descriptor capture plus `structuredClone` return. | Contract test mutates nested constructor input; returned proposal remains unchanged. |
| Phase 5C3B performs no authority resolution or semantic evaluation. | Relation proposal representation must not consume producer payloads or semantic binding logic. | `structural-findings/relation.ts`. | No reader, resolver, repository, evaluator, binder, or expectation dependency exists in the API. |
| Structural-findings public surface excludes findings and decision concepts. | Relation proposals must not accidentally expose later structural or decision artifacts. | Compiler-resolved export gate in `relation.test.ts`. | No public Gap/finding/Consequence/Decision Need/priority/score/ranking/recommendation/human-decision/action/outcome/feedback concepts or relation identity helpers. |
| Structural relation production remains generic. | The proposal contract must not acquire Career, Capability Core, matching, recommendation, legacy loop, Phase-5C2, or Phase-5C3A coupling. | AST module-specifier gate in `relation.test.ts`. | No forbidden production import. |

## Phase 5C3C structural-gap invariants

| Rule | Why | Enforcement location | Failure mode / contract |
| --- | --- | --- | --- |
| A gap requires an explicit expectation and an explicit represented basis. | Absence alone is not a Gap. | `structural-gaps/reconstruct.ts`. | One `StructuralExpectation` is compared per `reconstructStructuralGap(context, expectation, basis)` call. |
| A structural gap is basis-relative. | The represented basis is not a complete model of external reality. | Canonical gap body includes relevant observations from the supplied basis. | Different relevant non-satisfying bases can derive different `DGAP_` values; a satisfying basis returns `null`. |
| `null` is not global completeness. | One expectation can produce no gap without proving every expectation or the real world is complete. | Reconstruction return contract. | `null` means only this expectation is satisfied within this supplied basis. |
| CONTEXT_ROLE comparison is deterministic structural counting. | The context itself is the explicit observation basis for a role expectation. | `reconstructStructuralGap`. | IDs of matching-role context items are canonical; `observedCount === observedItemIds.length`; count at/above minimum returns `null`. |
| EBIND observations are structurally validated. | A fake or foreign proposal cannot serve as represented evidence. | `captureBinding`. | Exact shape, context, item, listed reference, disposition, trimmed rationale, and sealed `EBIND_` identity are required; otherwise `ERR_DECISION_STRUCTURAL_GAP_BINDING_INVALID`. |
| EBIND item/reference targets are unique in a basis. | Phase 5C3C must preserve the sealed Phase-5C2 one-binding-per-target invariant. | Binding ID and target-key sets. | Duplicate ID or distinct IDs for the same item/reference target fail `ERR_DECISION_STRUCTURAL_GAP_BASIS_INVALID`. |
| Irrelevant EBIND observations do not change `DGAP_`. | Only the expectation subject's represented observations belong to its derived body. | Relevant-binding filter and canonical binding-ID body. | Other-item bindings are validated but omitted from `observedBindingIds`. |
| DEPENDENCY comparison preserves direction. | A -> B is not B -> A. | Exact endpoint comparison. | Exact proposal returns `null`; reverse proposal does not satisfy but its ID is retained as relevant observation data. |
| CONTRADICTION proposals do not satisfy dependency expectations. | DREL proposal kinds have separate semantics. | Dependency-proposal filter. | Contradictions are omitted from dependency observation IDs and cannot satisfy. |
| DREL remains proposal data. | Structural consumption does not upgrade relation truth. | Sealed `assertStructuralRelationProposal` use. | Invalid/tampered DREL fails `ERR_DECISION_STRUCTURAL_GAP_RELATION_INVALID`; valid DREL is not relation truth. |
| `DGAP_` identity is deterministic. | The same represented derivation must have one derived-artifact identity. | `structural-gaps/identity.ts`. | SHA-256 tuple includes context, expectation, kind, and canonical body; `observedCount` is derived, not independently identity-bearing. |
| Structural gaps have no independent provenance. | Expectation provenance is already represented by `expectationId`; gap derivation must not add an ungoverned origin axis. | `StructuralGap` variants. | No provenance field exists on a gap. |
| Stored gap assertion is basis-bound. | Hash consistency is not derivation validity. | `assertStructuralGap(context, expectation, basis, gap)`. | It reconstructs against the exact basis; a supplied gap for a satisfying basis fails `ERR_DECISION_STRUCTURAL_GAP_INVALID`. |
| Stored gap arrays are already canonical. | Stored artifacts must not be silently repaired. | Stored assertion canonical-ID checks. | Reordered `observedBindingIds`, `observedItemIds`, or `observedRelationProposalIds` fail `ERR_DECISION_STRUCTURAL_GAP_INVALID`. |
| Basis and nested-artifact errors remain distinct from stored-gap errors. | A bad basis, EBIND, or DREL is not a bad stored gap. | Reconstruction before stored-gap validation in `assertStructuralGap`. | Basis wrapper/container: `BASIS_INVALID`; EBIND: `BINDING_INVALID`; DREL: `RELATION_INVALID`; bad stored gap: `INVALID`. |
| Phase 5C3C performs no authority, evaluator, detector, or graph work. | Gap reconstruction compares represented structure only. | `structural-gaps/reconstruct.ts` public API. | No reader, resolver, repository, payload, binder, evaluator, relation discovery, or graph traversal dependency exists. |
| Structural-gaps public surface excludes later decision concepts and remains generic. | The derived-gap module must not gain consequence or decision intelligence. | Export/import architecture gates in `structural-gaps/reconstruct.test.ts`. | No Career, Capability Core, matching, recommendation, or legacy-loop import; no Consequence, DecisionNeed, Priority, Score, Confidence, Ranking, Recommendation, HumanDecision, Action, Outcome, or Feedback export. |

## Phase 5C3D structural-consequence invariants

| Rule | Why | Enforcement location | Failure mode / contract |
| --- | --- | --- | --- |
| A consequence requires a validated item-anchored gap and one explicit ordered dependency path. | A Gap or a dependency proposal alone cannot establish a structural consequence. | `structural-consequences/reconstruct.ts`. | No unordered relation inventory or graph discovery API exists. |
| Source gaps are operation-locally revalidated. | `DGAP_` hash consistency is not derivation validity or a portable certificate. | Sealed `assertStructuralGap` and `reconstructStructuralGap` calls. | Sealed Phase-5C3C context, expectation, basis, binding, and relation errors propagate unchanged. |
| Source-gap validation order preserves sealed error ownership. | An invalid expectation must fail before a gap basis is inspected. | Context capture, expectation capture/validation, then gap-basis capture. | Invalid expectation: `ERR_DECISION_STRUCTURAL_GAP_EXPECTATION_INVALID`; valid expectation then malformed gap basis/artifact preserves the matching Phase-5C3C error. |
| Only item-anchored gaps propagate. | A role-count gap has no uniquely represented missing item. | Source-anchor derivation. | Evidence gap anchors at `subjectItemId`; dependency gap at `dependentItemId`; context-role gap fails `ERR_DECISION_STRUCTURAL_CONSEQUENCE_SOURCE_NOT_ITEM_ANCHORED`. |
| Propagation consumes one explicit ordered DEPENDENCY path. | Relation ontology must not become graph discovery or relation truth validation. | `StructuralConsequencePropagationBasis`. | No reachability search, downstream discovery, shortest-path computation, ranking, or relation inference occurs. |
| Path direction follows prerequisite to dependent. | Stored DREL direction is `dependentItemId depends on prerequisiteItemId`. | Linear path validation. | First prerequisite equals source; each prior dependent equals next prerequisite; final dependent is `affectedItemId`. |
| Path topology is locally finite. | A supplied propagating path must not repeat its own relation or item. | Relation-ID and visited-item sets. | Empty path, wrong kind, discontinuity, duplicate relation ID, or repeated item fails `ERR_DECISION_STRUCTURAL_CONSEQUENCE_PATH_INVALID`; this is not a global acyclicity claim. |
| DREL failure differs from path failure. | A malformed/tampered relation is not a valid relation in bad topology. | Defensive nested relation capture then sealed relation assertion. | Invalid DREL: `ERR_DECISION_STRUCTURAL_CONSEQUENCE_RELATION_INVALID`; valid DREL with invalid topology: `ERR_DECISION_STRUCTURAL_CONSEQUENCE_PATH_INVALID`. |
| `DCONS_` identity is deterministic and path order is identity-bearing. | One source gap plus one explicit path must have a stable local derivation identity. | `structural-consequences/identity.ts`. | SHA-256 tuple contains schema, context, source gap, and ordered path IDs; different paths differ even if they share an affected item. |
| Consequence endpoint fields are derived. | The caller must not independently choose source or affected item. | Reconstructed source anchor and final dependent. | Stored source/affected/path body differing from reconstruction fails `ERR_DECISION_STRUCTURAL_CONSEQUENCE_INVALID`. |
| Stored consequence assertion is derivation-bound. | A self-consistent DCONS hash for another path must not be accepted. | `assertStructuralConsequence`. | Exact inputs reconstruct before stored representation is accepted; only an otherwise exact wrong ID yields `ERR_DECISION_STRUCTURAL_CONSEQUENCE_ID_MISMATCH`. |
| Returned consequences detach from caller input. | Later mutation of supplied gaps or relation proposals cannot alter the returned consequence. | Defensive capture plus detached return. | Contract tests mutate caller-owned DREL input after reconstruction. |
| Structural consequence is not a real-world effect or decision artifact. | Structural propagation must not acquire prediction, severity, priority, Decision Need, recommendation, or human decision semantics. | Closed `StructuralConsequence` fields and export gate. | No provenance, rationale, score, probability, confidence, severity, priority, recommendation, decision, action, outcome, or feedback field/export. |
| Structural-consequences production remains generic and adjacent. | Consequence derivation must not widen sealed predecessor barrels or import domain semantics. | `structural-consequences` module/export and import gates. | No Career, Capability Core, matching, recommendation, or legacy-loop import; `structural-findings` and `structural-gaps` exports remain unchanged. |

## Phase 5C4 validation-assembly invariants

| Rule | Why | Enforcement location | Failure mode / contract |
| --- | --- | --- | --- |
| A validation assembly records derivational coherence only. | Revalidating structural derivations cannot establish truth, completeness, current authority, semantic verification, or decision readiness. | `validation-assembly/reconstruct.ts`. | No authority flag, score, recommendation, Decision Need, or human-decision field or API exists. |
| The Decision Context remains `NOT_RUN`. | Phase 5C4 produces a separate artifact rather than mutating or upgrading a `DecisionContextDraft`. | Sealed Phase-5B draft contract and closed assembly fields. | No `ValidatedDecisionContext` or `validationStatus: "VALIDATED"` state is constructed. |
| Empty assembly input is valid. | Phase 5C4 has no implicit completeness requirement. | Canonical assembly reconstruction. | Empty expectation and consequence arrays produce an empty assembly, not a completeness proof. |
| Each expectation result is reconstructed locally. | Caller-supplied `null` or gap content is not derivation authority. | Sealed `reconstructStructuralGap` and, for gaps, `assertStructuralGap`. | Matching canonical `null` becomes `NO_GAP`; matching canonical gap becomes `GAP`; disagreement fails `ERR_DECISION_VALIDATION_ASSEMBLY_RESULT_MISMATCH`. |
| `NO_GAP` is basis-scoped only. | A null Phase-5C3C result is neither truth nor global satisfaction. | Closed result union. | `NO_GAP` means only no StructuralGap under this explicit represented basis. |
| The assembly commits to the complete derivation basis. | A `DGAP_` commits only to the relevant Phase-5C3C gap body, not necessarily every supplied observation. | `StructuralValidationBasisDescriptor` plus assembly `contextId`. | EVIDENCE_BINDING and DEPENDENCY descriptors carry complete canonical supplied observation-ID inventories; CONTEXT_ROLE is kind-only because its canonical context observations are already bound by `contextId`. Canonical ID arrays are code-point sorted, duplicates reject, and a different descriptor changes `DVASM_`. |
| One expectation ID occurs at most once per assembly. | Different basis evaluations must not be silently merged. | Expectation-result identity set. | `ERR_DECISION_VALIDATION_ASSEMBLY_DUPLICATE_EXPECTATION`. |
| A consequence requires its exact assembled GAP source derivation. | A self-consistent `DCONS_` alone cannot establish assembly coherence. | Sealed `assertStructuralConsequence` plus source-result lookup. | Same expectation ID, canonical gap-basis descriptor, and gap ID are required; missing source fails `ERR_DECISION_VALIDATION_ASSEMBLY_CONSEQUENCE_SOURCE_MISSING`. |
| A GAP may have zero or multiple consequences. | Gap and consequence remain distinct structural artifacts. | Consequence collection. | No consequence is synthesized; distinct consequence IDs may share one GAP source. |
| Consequence IDs and expectation results are canonical. | Input order must not create a different assembly. | Code-point sorting before identity construction. | Duplicate consequence ID fails `ERR_DECISION_VALIDATION_ASSEMBLY_DUPLICATE_CONSEQUENCE`; input ordering does not change `DVASM_`. |
